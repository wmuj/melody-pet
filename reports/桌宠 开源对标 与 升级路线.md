## 网易云的开源组件，不能证明桌宠业务已开源

本轮检查了网易官方开源入口、NetEase 组织公开仓库的名称与简介，以及相关 GitHub 检索结果，没有找到能建立官方归属的完整桌宠仓库。这是**限定检索范围内的结论**，不代表已经证明所有组织、历史版本或非公开仓库都不存在。网易确实有开源项目，但仓库与网易云业务有关，也不自动等于桌宠源码。([网易开源](https://opensource.netease.com/home)) ([NetEase 公开仓库目录](https://api.github.com/orgs/NetEase/repos?per_page=100&type=public))

本机网易云安装目录存在 `libcef.dll`，文件资源确认其为 Chromium Embedded Framework。CEF 是嵌入浏览器的开源基础设施，不能据此推定角色动画、动作逻辑和产品代码也开放。第三方 **Open Orpheus** 明确声明与网易没有关联、授权或认可，并且不包含网易资产或代码；**NeteaseCloudMusicApi** 是另一类 API 服务项目。这三者都不能作为“网易官方桌宠已经开源”的证明。([本机文件证据](<E:/网易云桌宠/research_notes/桌宠 开源对标 与 升级路线/evidence_netease/local_installed_files.json>)) ([CEF](https://github.com/chromiumembedded/cef/blob/master/README.md)) ([Open Orpheus 声明](https://github.com/YUCLing/open-orpheus/blob/main/README.md)) ([API 项目](https://github.com/Binaryify/NeteaseCloudMusicApi))

目前可读的二级报道描述网易云桌宠会随播放状态跳舞或睡觉、响应点击与拖动、显示歌词，可以用来设计对照场景；本轮没有实际评测它，也没有核实完整官方功能和收费规则。因此，不能把报道里的“动作生硬”等评价当成我们测出的缺陷，更不能提前宣布已经胜出。([产品报道](https://post.smzdm.com/p/avgpvx3p/))

## 当前已经能用，尚缺支撑“超越”的完整体验证据

**已有验证记录支持的能力**包括小鲸鱼显示与表情、摸摸喂食、原生窗口移动和拖拽、睡眠唤醒、声音设置与立即静音、PNG 导入，以及构建和五项自动测试通过。中文 SAPI 合成生成了非静音 WAV；这证明实际合成链路工作，并不等于已经人工试听音色。当前程序独立使用 Electron／React／Canvas 和 Windows 原生接口，具备继续打磨的基础。([项目说明](<E:/网易云桌宠/README.md>)) ([验证记录](<E:/网易云桌宠/docs/验证记录.md>))

**距离成熟音乐伙伴仍有明确差距**：中文回复主要来自固定短句，口型按说话状态开合；养成主要体现为好感和固定互动。当前真实 SMTC 检查是 `hasSession: false`，切歌播报使用模拟事件，尚不能宣称真实网易云、QQ 音乐和 Spotify 全部联调通过。完整透明视频包、其他应用上的物理鼠标穿透、多显示器和游戏全屏仍缺实际场景验证，也没有独立安装包。([能力与限制](<E:/网易云桌宠/README.md>)) ([具体测试边界](<E:/网易云桌宠/docs/验证记录.md>))

因此，“更可爱、更自然、更省资源”目前都应作为待验证目标。竞品文档展示了它们已经实现的机制，不能直接证明实际体验一定好；我们的测试通过也不能直接证明用户会更喜欢。后续比较应让同一用户在同一设备上完成相同操作，分别记录错误、等待、打扰和主观偏好。没有证据表明先改写成 Rust 或 WPF 比打磨动作、台词和稳定性更有收益。

## 下一版先完成三个连贯改进，再扩大能力范围

**第一优先是角色动作和本地中文互动。** 建议先完成约八组能衔接的核心动作：待机、摸摸、进食、起跑、刹停、拖放回弹、听歌、睡醒。重点是起势与收尾、视线和身体的协调，以及人工互动能自然打断自动行为。台词按首次见面、摸摸、投喂、连续打扰、返回桌面、播放、切歌和睡觉选择，加入近期防重复、冷却和夜间安静策略；眼神、气泡、声音和嘴巴共同开始与结束。现有本地 SAPI 路线继续保留，无需先配置模型账户。

**第二个改进是记住真实发生过的互动。** 在已有昵称和好感基础上，保存投喂、摸摸、一起听歌等真实事件的时间与计数，让初识、熟悉、连续打扰有不同反应。例如当天确实喂过，才说“今天的小鱼干已经吃过啦”；音乐事件没有确认，就不生成共同听歌的回忆。记录可查看和清空，先做有限、可解释的相处历史。更复杂的饥饿、心情和关系阶段可以随后加入，避免第一版就变成需要照料大量数值的游戏。

**第三个改进是让音乐真正改变角色行为。** 先以真实网易云会话闭环：播放时戴耳机进入聆听，暂停后放松，切歌只在合适时给短回应。取得真实音频后，再把音量能量和节拍分别映射到身体、尾巴和鳍；没有信号就保持普通待机，不能用随机摆动冒充踩点。AIRI 已有节拍联动，我们争取的是原创鲸鱼的表现力，以及不频繁盖过歌曲的陪伴分寸。上述三项可组成第一版小范围升级；当前尚未收到新的优先级选择，本文将其作为建议，不冒充用户已确认的版本承诺。

随后优先补跨窗口可靠性、完整动作包和安装交付：实测鼠标穿透、全屏避让、不同 DPI、多屏和睡眠恢复；覆盖透明 WebM／GIF 的导入、缺失动作回退和预览；制作安装包并保留既有数据。再做长时间资源测量与必要优化。**自由聊天、麦克风 ASR 和大模型接入放到后续可选增强**，不成为使用小鲸鱼的门槛。

## 把“超越”变成可展示的版本成果

最有价值的成果，是用户真的愿意每天留着这只鲸鱼：摸它时反应自然，听歌时有陪伴感，忙碌时知道安静，重启后仍记得相处。完成上述小范围版本并让用户看过、听过，再选择最接近的竞品做同场景对照，才能把“我想超过它们”推进成“这一项我们已经做得更好”。这轮报告完成了对标与路线设计，尚未实施以上升级，也没有产生竞品胜负或用户审美验收结论。

## 2026-11-13 后续开发更新：1.2

用户进一步明确要蓝发「大肥鱼」鲸娘，并用截图指出尾巴裁切、左侧多余图块和模糊。默认素材已从 192×208 单帧图集改为 984×984 独立待机图与约 640 像素互动姿态；按真实 DPI 绘制，完成左右跑动、摸摸、喂食、拖放和睡醒的实际窗口检查。台词增加近期避重复和情境，相处日记记录真实事件；Codex Pets V1/V2 导入和清空／重启路径已验证。最终构建和 10 项自动测试通过。

真实网易云已报告 `cloudmusic.exe`、歌曲和 Playing 状态，但当前客户端的进度与时长均为 0。现在以不显示同步歌词来避免卡住，不能表述为歌词联动已全部完成。角色素材来源与使用条件在 [来源说明](<E:/网易云桌宠/THIRD_PARTY_NOTICES.md>) 中分别保留。

本次动作仍是高清姿态加程序动画，用户尚未完成审美验收。上表的 20 轮复杂动作链、播放器多次对照、真实多屏、8 小时性能和竞品体验比较，仍是后续验收目标；本次没有产生“已经超越”的结论。
